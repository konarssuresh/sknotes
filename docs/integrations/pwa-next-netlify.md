# PWA on Next.js 16 + Netlify

## Decision (Phase 7 PR3)

| Option                        | Outcome                                                                                                                                                                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Serwist / `@serwist/next`** | Strong precache integration with the Next build, but adds a webpack/turbopack hook surface we have not validated on Next **16.4** with `cacheComponents` and Turbopack CSS rules.                                                                                       |
| **Manual `public/sw.js`**     | **Chosen.** Small, reviewable worker; explicit network-only list for auth, API, and `(app)` navigations; versioned static precache only. Works with `@netlify/plugin-nextjs` because the SW is a static file under `public/` and does not alter the Next server bundle. |

Netlify continues to run `npm run build` and publish via the Next plugin ([`netlify.toml`](../netlify.toml)). No Netlify-specific SW headers are required; `sw.js` is served from the site root.

## Installability

- Web app manifest: [`app/manifest.js`](../../app/manifest.js) (App Router metadata file).
- Icons: [`app/icon.svg`](../../app/icon.svg) plus PNGs in [`public/icons/`](../../public/icons/) generated by `node scripts/generate-pwa-icons.mjs` (requires `sharp` devDependency).
- Service worker: [`public/sw.js`](../../public/sw.js), registered from [`components/pwa/service-worker-register.jsx`](../../components/pwa/service-worker-register.jsx).

## Caching policy

1. **Runtime cache:** `/_next/static/*` uses **network-first** (offline fallback to cache). `/icon.svg` and `/icons/*` may use cache. **`SKNOTES_SW_VERSION`** is set automatically at **`npm run build`** by [`scripts/inject-sw-version.mjs`](../../scripts/inject-sw-version.mjs) (package version + git SHA + UTC date). The committed worker keeps placeholder `__SKNOTES_SW_VERSION__`; CI unit tests fail if the network-first policy regresses.
2. **Network-only:** `/api/*`, auth pages, and all signed-in app routes (`/`, `/notes/*`, `/tags`, `/settings`, archive/trash, etc.). Document navigations are never stored in Cache Storage.
3. **Cookies / sessions:** No `cache.put` on HTML or API responses; default handler is `fetch()` only.
4. **Logout:** [`clearClientSessionState`](../offline-resilience.md) clears TanStack Query and deletes all Cache Storage keys so another account on the same browser profile does not reuse cached shells.

Policy helpers are unit-tested in [`tests/unit/pwa-cache-policy.test.js`](../../tests/unit/pwa-cache-policy.test.js) and [`tests/unit/pwa-sw-source.test.js`](../../tests/unit/pwa-sw-source.test.js) (shared rules with the worker).

## Registration

- **Production:** SW registers on load.
- **Development:** disabled (avoids stale caches while iterating).
- **E2E / manual PWA checks:** set `NEXT_PUBLIC_E2E_PWA=1` to register in non-production builds.
- **After deploy:** clients compare `meta[name=sknotes-sw-version]` with stored version, clear Cache Storage when it changes, activate waiting workers (`SKIP_WAITING`), and reload once. Chunk / RSC load failures trigger a single automatic reload before showing [`app/global-error.js`](../../app/global-error.js).

## User workaround: “This page couldn’t load” (normal tab, Incognito works)

Usually stale service worker or cache after a deploy. **iPhone Chrome:** ⋮ → Settings → Privacy and security → Clear Browsing Data → **All time** → enable **Cached images and files** and **Cookies, site data** → clear, then open the site in a normal tab (sign in again). Remove any Home Screen shortcut and re-open in Chrome if needed.

## Manual cross-account check

1. Build and start production server (`npm run build && npm run start`) with `NEXT_PUBLIC_E2E_PWA=1` if testing locally.
2. Sign in as User A, open a note with distinctive title.
3. Sign out (Settings → Sign out).
4. Sign in as User B — User A’s note title must not appear in the list or editor.
5. In DevTools → Application → Cache Storage, confirm no HTML entries for `/notes` after logout.

Automated coverage: Phase 6 IndexedDB isolation tests plus the cache-policy unit tests; full multi-user browser E2E is optional when auth seeding is available.

## Out of scope

Background Sync, push notifications, and offline listing of the full notes catalog (see Phase 7 plan).
